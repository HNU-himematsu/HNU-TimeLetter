# 智能体文档与知识图谱规范协议

## 1. 核心原则：单一事实来源 (SSOT)
所有智能体（Agents）在创建、更新或引用文档时，必须严格遵守 DRY (Don't Repeat Yourself) 原则。任何结构化知识、全局配置或领域定义，绝不允许在代码库或文档库的多处重复存在。

## 2. 强制语法：Obsidian 风格链接与相对路径
智能体必须使用以下语法来维护文档间的网络拓扑关系，并严格遵守寻址路径规范：

### A. 路径规范：强制使用相对路径
- **约束规则：** 在编写任何双向链接或嵌入调用时，必须使用相对于当前文档的相对路径。绝对禁止使用绝对路径或纯文件名，以确保文档库跨系统、跨环境的绝对可移植性，并彻底避免同名文件带来的解析歧义。

### B. 概念引用（双向链接）：`[[ ]]`
- **何时写入：** 当提及拥有专属文档的实体、模块、概念或流程时，必须使用 `[[相对路径/文档名称]]` 语法。
- **约束规则：** 绝对不要在当前上下文中重新解释或概括已被链接的概念，请完全依赖该链接作为概念说明。
- **如何读取：** 当智能体在处理任务时遇到 `[[ ]]`，且评估自身缺乏足够上下文来完成当前任务时，必须在继续执行下一步前，自主解析相对路径，检索并读取目标源文档。

### C. 内容嵌入（块引用）：`![[ ]]`
- **何时写入：** 当需要内联展示另一份文档的具体内容时（例如：共享的数据 Schema、全局约束规则），必须使用 `![[相对路径/文档名称#标题]]` 语法。
- **约束规则：** 绝对禁止对共享状态进行硬编码（Hardcoding）。如果某段信息需要在多个模块间共享或流转，必须将其提取为独立的 Markdown 文件，并通过带有相对路径的嵌入语法进行调用。
- **如何读取：** 智能体必须将 `![[ ]]` 视为动态引入（Dynamic Include）。在处理读取逻辑时，智能体必须根据当前文件的目录层级解析相对路径指针，检索目标文件的真实内容，并将其注入到当前的工作上下文中理解。

## 3. 智能体文档生成行为准则
当接收到生成新文档或更新现有文档的指令时，智能体必须执行以下步骤：
1. **优先检索 (Discover First)：** 在创建任何新的定义、架构描述或配置片段之前，必须首先检查当前目录或全局共享库中是否已经存在该概念的单一事实源文件。
2. **模块拆分 (Decompose)：** 如果要求生成的文档中包含独立的、具有高复用潜力的子模块，必须将这些子模块提取为同级或子目录下的独立 `.md` 文件，然后使用 `![[ ]]` 相对路径语法来组装成最终的主文档。
3. **可追溯性 (Traceability)：** 确保每一个新生成的文档都使用了 `[[ ]]` 语法，指回（链接至）其隶属的父模块、史诗任务（Epic）或相关的架构决策记录（ADR）。
