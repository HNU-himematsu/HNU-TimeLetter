# 新增同步表操作手册

> 适用版本：同步系统 v1.1+（`SyncTableKey` 从 `SyncTableOutputMap` 派生）

---

## 核心约束：单一事实来源

`SyncTableKey` 的定义如下，永远不要手动修改它：

```ts
// src/lib/sync/types.ts
export type SyncTableKey = keyof SyncTableOutputMap;
```

**新增同步表只需在 `SyncTableOutputMap` 中添加一个键值对。**  
`SyncTableKey` 自动跟进，TypeScript 编译器会在漏填任何步骤时报错。

---

## 完整步骤

### 第 1 步：定义输出类型

若新表的输出类型尚未在 `src/lib/types.ts` 中定义，先在此处添加：

```ts
// src/lib/types.ts
export interface MyNewEntry {
  id: string;
  name: string;
  // ... 其他字段
}
```

### 第 2 步：在 `SyncTableOutputMap` 注册输出类型

```ts
// src/lib/sync/types.ts
import type { ..., MyNewEntry } from '../types';

export interface SyncTableOutputMap {
  locations: LocationCoords;
  stories: LocationPoint[];
  creation_headers: CardHeaderInfo[];
  creation_board: CreationIdea[];
  contributors: Contributor[];
  my_new_table: MyNewEntry[];   // ← 在此追加
}
```

完成后 `SyncTableKey` 自动变为 `'locations' | 'stories' | ... | 'my_new_table'`。

### 第 3 步：实现写入器（可选）

若需要将产物写入 `src/data/` 或 `src/config/`，创建写入器：

```ts
// src/lib/sync/writers/my-new-table.writer.ts
import * as path from 'node:path';
import type { MyNewEntry } from '../../types';
import { writeJsonFile } from './json-writer';

export const MY_NEW_TABLE_FILE_PATH = 'src/data/my-new-table.json';

const file = path.resolve(process.cwd(), MY_NEW_TABLE_FILE_PATH);

export function writeMyNewTable(entries: MyNewEntry[]) {
  writeJsonFile(file, { entries });
  return MY_NEW_TABLE_FILE_PATH;
}
```

`writeJsonFile` 内置"先写临时文件再原子替换"与空结果保护（若 `entries` 为空不覆盖已有文件）。

### 第 4 步：实现表模块

```ts
// src/lib/sync/tables/my-new-table.module.ts
import type { MyNewEntry } from '../../types';
import type { TableSyncModule } from '../types';
import { getText } from '../shared/field-reader';
import { writeMyNewTable } from '../writers/my-new-table.writer';

export const myNewTableModule: TableSyncModule<'my_new_table'> = {
  key: 'my_new_table',
  label: '新表（后台显示名称）',
  // 若本表需要先跑其他表，声明依赖：
  // dependsOn: ['locations'],
  async run(ctx) {
    if (!ctx.settings.feishuMyNewTableId) {
      throw new Error('缺少 FEISHU_MY_NEW_TABLE_ID，无法同步新表');
    }

    const records = await ctx.services.feishuBitable.listRecords(
      ctx.settings.feishuMyNewTableId,
    );

    const entries: MyNewEntry[] = [];
    for (const record of records) {
      const id = getText(record.fields['ID']).trim();
      if (!id) continue;
      entries.push({
        id,
        name: getText(record.fields['名称']).trim(),
      });
    }

    const filePath = writeMyNewTable(entries);

    return {
      output: entries,
      filesWritten: [filePath],
      summary: {
        totalRecords: records.length,
        successRecords: entries.length,
        skippedRecords: records.length - entries.length,
        failedRecords: 0,
      },
      warnings: [],
    };
  },
};
```

**泛型约束**：`TableSyncModule<'my_new_table'>` 确保 `run()` 的返回值与 `SyncTableOutputMap['my_new_table']` 严格对应，类型错误会在编译期暴露。

### 第 5 步：注册到 `registry.ts`

```ts
// src/lib/sync/registry.ts
import { myNewTableModule } from './tables/my-new-table.module';

export const tableRegistry = {
  locations: locationsModule,
  stories: storiesModule,
  creation_headers: creationHeadersModule,
  creation_board: creationBoardModule,
  contributors: contributorsModule,
  my_new_table: myNewTableModule,   // ← 在此追加
} satisfies Record<SyncTableKey, TableSyncModule>;
```

`satisfies Record<SyncTableKey, TableSyncModule>` 会验证 `tableRegistry` 包含 `SyncTableOutputMap` 的所有键，遗漏时编译报错。

### 第 6 步：添加环境变量声明（可选）

若新表需要独立的飞书表 ID，在 `SyncEnvironmentSettings` 中声明：

```ts
// src/lib/sync/types.ts
export interface SyncEnvironmentSettings {
  // ... 已有字段
  feishuMyNewTableId?: string;
}
```

并在 `src/lib/sync/clients/feishu-env.ts`（或初始化服务的地方）读取对应环境变量 `FEISHU_MY_NEW_TABLE_ID`。

### 第 7 步：加入默认同步集（可选）

若希望每次自动同步都包含新表，修改运行时配置：

```json
// runtime/admin/sync-config.json
{
  "defaultTables": ["locations", "stories", "creation_headers", "creation_board", "contributors", "my_new_table"]
}
```

## 快速验证清单

完成以上步骤后，运行：

```bash
# 1. 类型检查（有任何遗漏步骤会在此报错）
npm run typecheck

# 2. 本地试跑
npx tsx src/scripts/sync-all.ts
```

`npm run typecheck` 零错误即视为新表接入完整。

## 依赖声明规范

若新表的飞书数据依赖另一张表的本地产物文件，声明 `dependsOn`：

```ts
export const myNewTableModule: TableSyncModule<'my_new_table'> = {
  dependsOn: ['locations'],   // 确保 locations 先执行
  // ...
};
```

依赖链由 `registry.ts` 中的 `sortTablesForExecution` 拓扑排序解析，循环依赖会在运行时抛出 `SyncValidationError`。

**注意**：`dependsOn` 列表中的表必须也在 `SyncTableOutputMap` 中存在，否则 TypeScript 会拒绝编译。

## 常见错误与原因

| 错误信息 | 原因 | 修复 |
|---|---|---|
| `Type '"my_new_table"' is not assignable to type 'keyof SyncTableOutputMap'` | 遗漏了第 2 步 | 在 `SyncTableOutputMap` 添加新键 |
| `Property 'my_new_table' is missing in type ... satisfies Record<SyncTableKey, ...>` | 遗漏了第 5 步 | 在 `tableRegistry` 注册模块 |
| `Type ... is not assignable to type 'TableSyncResult<"my_new_table">'` | `run()` 返回的 `output` 类型与 `SyncTableOutputMap['my_new_table']` 不一致 | 修正模块返回类型 |
| CI 安全审计失败（`npm audit --audit-level=high`） | 生产依赖引入了高危漏洞 | 运行 `npm audit fix` 升级受影响包 |
