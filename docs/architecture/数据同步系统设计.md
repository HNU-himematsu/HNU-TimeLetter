# 数据同步系统架构

> 版本：v1.0（实现版）
> 适用前提：自托管服务器 · 单实例 Next.js / Node.js 常驻进程

---

## 1. 背景与定位

本系统为《与她的海大时光笺》提供一条可运行的飞书 → 站点数据同步链路。

**同步链路能力：**

1. 从飞书多维表格读取地点、故事、创作公示板、鸣谢名单数据
2. 下载飞书附件并上传至 OSS
3. 将 OSS URL 回写至飞书多维表格
4. 输出前端直接消费的本地 JSON 产物文件
5. 通过后台页面手动触发，或通过定时任务自动执行

**数据发布模式：`build_time`**

产物文件（`src/data/*.json`、`src/config/locations.json`）视为**构建期数据**，
同步完成后必须经过 `next build + restart` 才能使线上页面读取到新内容。

---

## 2. 部署前提

| 条件 | 说明 |
|---|---|
| 部署环境 | 自托管服务器，非 Serverless / 容器编排 |
| 进程模型 | 单实例常驻 Node.js 进程（PM2 管理） |
| 文件系统 | 本地文件系统作为 v1 运行期状态存储 |
| 定时任务 | `node-schedule`，随进程启动初始化 |
| 并发策略 | 单任务串行，同一时刻最多一个 running job |

> 若未来转为多实例、容器编排或蓝绿部署，需迁移到外部调度器与分布式锁。

## 4. Job 模型

### 4.1 任务类型

| kind | 说明 |
|---|---|
| `sync-data` | 从飞书多维表格同步数据到 `src/data/` 与 `src/config/` 下的 JSON 产物文件 |

### 4.2 任务状态流转

```
queued → running → success
                 → partial_success
                 → failed
```

### 4.3 步骤状态

每个表模块执行一个步骤：

| 值 | 说明 |
|---|---|
| `running` | 执行中 |
| `success` | 全部成功 |
| `success_with_warnings` | 有部分记录失败，但产物已生成 |
| `skipped` | 因依赖缺失或任务终止被跳过 |
| `failed` | 失败 |

### 4.4 核心类型定义（`src/lib/sync/types.ts`）

```ts
export type SyncJobKind = 'sync-data';

/**
 * SyncTableKey 从 SyncTableOutputMap 的键派生。
 * 新增同步表只需在 SyncTableOutputMap 添加一个键值对，
 * SyncTableKey 自动跟进，无需单独维护。
 */
export type SyncTableKey = keyof SyncTableOutputMap;

export interface SyncTableOutputMap {
  locations: LocationCoords;
  characters: Character[];
  stories: LocationPoint[];
  creation_headers: CardHeaderInfo[];
  creation_board: CreationIdea[];
  contributors: Contributor[];
}

export type DependencyMode = 'read_local' | 'run_dependencies' | 'strict';

export interface SyncJobRecord {
  jobId: string;
  kind: SyncJobKind;
  status: 'queued' | 'running' | 'success' | 'partial_success' | 'failed' | 'canceled';
  tables: SyncTableKey[];
  effectiveTables: SyncTableKey[];
  dependencyMode: DependencyMode;
  includeAssets: boolean;
  continueOnTableError: boolean;
  triggeredBy: 'admin-ui' | 'scheduler' | 'cli' | 'webhook';
  note?: string;
  createdAt: string;
  startedAt?: string;
  syncedAt?: string;
  finishedAt?: string;
  durationMs?: number;
  steps: SyncJobStep[];
  summary?: Record<string, unknown>;
  warnings: string[];
  errors: string[];
}

export interface SyncJobStep {
  step: string;
  status: 'pending' | 'running' | 'success' | 'success_with_warnings' | 'skipped' | 'failed';
  startedAt?: string;
  finishedAt?: string;
  summary?: {
    totalRecords?: number;
    successRecords?: number;
    skippedRecords?: number;
    failedRecords?: number;
    filesWritten?: string[];
    [key: string]: unknown;
  };
  warnings?: string[];
  errors?: string[];
}
```

## 5. 表注册表（Table Registry）

所有可同步的表以模块形式注册，后续新增表只需扩展注册表。

| key | 说明 | 输出文件 | 依赖 |
|---|---|---|---|
| `locations` | 飞书地点表 | `src/config/locations.json` | 无 |
| `characters` | 飞书角色表（含头像 OSS 回填） | `src/data/characters.json` | 无 |
| `stories` | 飞书展示表 | `src/data/content.json`（含地点） | `locations`, `characters` |
| `creation_headers` | 便签头表（地点 + 角色元数据） | `src/data/creation-board-headers.json` | 无 |
| `creation_board` | 创作公示板（便签内容） | `src/data/creation-board.json` | `creation_headers` |
| `contributors` | 鸣谢名单 | `src/data/contributors.json` | 无 |

**注册代码位于 `src/lib/sync/registry.ts`**

```ts
export const tableRegistry = {
  locations: locationsModule,
  characters: charactersModule,
  stories: storiesModule,
  creation_headers: creationHeadersModule,
  creation_board: creationBoardModule,
  contributors: contributorsModule,
} satisfies Record<SyncTableKey, TableSyncModule>;
```

以下内容均从注册表派生：
- API 参数校验（有效 key 集合）
- 后台可选表清单
- 默认表集合
- 依赖解析顺序

## 6. 依赖处理模式

| 模式 | 说明 | 适用场景 |
|---|---|---|
| `read_local` | 只跑所选表，依赖从本地产物读取 | 默认推荐，轻量刷新 |
| `run_dependencies` | 自动补跑依赖表 | 需要全量更新依赖链 |
| `strict` | 依赖缺失即失败 | 严格验证场景 |

## 7. 触发入口统一

三种触发方式均通过同一编排器入口：

**CLI**
```ts
await runSyncJob({
  kind: 'sync-data',
  tables: ['locations', 'stories', 'creation_board'],
  triggeredBy: 'cli',
});
```

**API**
```ts
// POST /api/admin/sync/jobs
await createSyncJob({
  kind: 'sync-data',
  tables: ['locations', 'stories'],
  triggeredBy: 'admin-ui',
});
```

**Scheduler**
```ts
await createSyncJob({
  kind: 'sync-data',
  tables: config.defaultTables,
  triggeredBy: 'scheduler',
});
```

## 8. 并发与锁

- **锁文件**：`runtime/admin/sync-lock.json`
- **超时时间**：30 分钟（`SYNC_LOCK_TIMEOUT_MS` 可覆盖）
- **并发策略**：新任务与 running job 冲突时返回 `409 Conflict`，响应带 `currentJobId`
- **锁过期恢复**：将旧 job 标记为 `failed`，释放锁后允许新任务进入

锁文件结构：

```json
{
  "jobId": "sync-1746028800000-ab12",
  "pid": 12345,
  "createdAt": "2026-04-30T10:00:00.000Z",
  "expiresAt": "2026-04-30T10:30:00.000Z"
}
```

## 9. 文件写入策略

所有产物文件采用"先写临时文件再替换"方式，防止写入中途崩溃导致文件损坏：

```
序列化 JSON → 写入 *.tmp → 校验合法性 → rename 到目标路径
```

**空结果保护**：若飞书返回空数据，不覆盖本地已有产物文件，记录 warning 后跳过。

---

## 10. 运行时数据生效路径

```
飞书多维表格（数据源）
    ↓ 同步任务（定时 / 手动 / Webhook）
src/data/*.json 与 src/config/*.json（产物文件）
    ↓ 运行时 API
前端页面
```

同步完成后 JSON 产物文件即更新，前端通过运行时 API 读取最新数据，不需要重新构建或重启服务。

## 11. 日志与任务存储

### 11.1 任务存储

- 存储路径：`runtime/admin/sync-jobs/<jobId>.json`
- 上限：100 个文件，超出自动清理最早记录

### 11.2 同步日志

- 存储路径：`logs/sync/<jobId>.log`
- 每个任务独立日志文件，防止日志无限增长
- 通过 `GET /api/admin/sync/jobs/<jobId>/logs` 读取最后 200 行

### 11.3 `.gitignore`

```gitignore
/runtime/
/logs/
*.tmp
```

## 12. 新增飞书表流程

详细操作手册见 [新增同步表指南](../guides/新增同步表.md)。

**核心设计约束**：`SyncTableKey` 从 `SyncTableOutputMap` 的键派生，二者无法失步。
新增表时 **只需**扩展 `SyncTableOutputMap`，不要手动修改 `SyncTableKey`。

| 步骤 | 文件 | 操作 |
|---|---|---|
| 1 | `src/lib/sync/types.ts` | 在 `SyncTableOutputMap` 添加 `新key: 输出类型` |
| 2 | `src/lib/types.ts` | 如需新类型，在此定义并 import 进 types.ts |
| 3 | `src/lib/sync/tables/<new>.module.ts` | 实现 `TableSyncModule<'新key'>` |
| 4 | `src/lib/sync/writers/<new>.writer.ts` | 实现产物文件写入器（可选） |
| 5 | `src/lib/sync/registry.ts` | 在 `tableRegistry` 中注册模块 |
| 6 | `runtime/admin/sync-config.json` | 若需默认触发，加入 `defaultTables` |
